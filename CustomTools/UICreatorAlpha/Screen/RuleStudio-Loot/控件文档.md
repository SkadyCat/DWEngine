# RuleStudio 地面掉落原型

独立工程 `opus-rulestudio-loot-20261025`，设计尺寸 1600 × 900。全部游戏 UI 由 UICreator SVG 资产、文本节点、按钮四态和预制体组成；预览页顶部按钮、底部检查结果和地面示意属于工具环境。

- 交互原型：`http://127.0.0.1:5190/examples/loot-prototype.html`
- 编辑工程：`http://127.0.0.1:5190/?project=opus-rulestudio-loot-20261025&interface=ground`
- `loot.uialpha.json` 是可再次导入的完整工程。
- `screen.html` 是数据为空的结构预览（服务地址 `/examples/loot-structure.html`）；`screen.reference.html` 指向带真实规则样例的交互预览。
- `Controls/` 是 59 个独立 SVG 资源的等尺寸 HTML 预览；文字、通货等级和物品值没有烘焙到资源中。

## 层级

1. 地面掉落概况：显示数量、地面剩余数量、成功领取数量。
2. 地面标牌层：五种品质、三阶通货、特殊通货、征兆共十个预制体；名称与等级标记为独立文本；支持普通、悬停、按下、禁用状态。
3. Hunter 面板：启用开关、全部 789 种现有词条搜索、每页 12 种、装备 AND 条件、仅看已选、清空词条、通货条件与显示数量。
4. 物品详情：悬停显示、Ctrl 固定、Esc/按钮关闭、点击靠近拾取。
5. 操作提示：点击名称靠近、WASD 取消、Z 显示掉落。

全部文本声明安全区与 overflow 策略。标牌名称超过 260 px 时省略，完整名称通过详情显示。UI 资产使用 SVG，保留编辑能力。

## 同源逻辑

`src/assets/loot-prototype/reference/` 包含 RuleStudio 的源快照和 SHA-256 清单。原型直接调用其中的 `FloorRewards.onKill / pickup / grantLoot`、`hunterAllows` 与 `lootStyle`。喷散、落地与落地后显名使用原 `loot-markers` 的轨迹函数。1028 份当前规则文档来自 Beta 的 Content/Rules，未使用测试替换规则。

- 普通怪装备、道具掉率使用原默认值；首领使用原保证掉落逻辑。
- 拾取距离为 200 cm；超距、死亡、背包堆叠上限、重复领取先校验再修改。
- 点击标牌自动靠近，WASD 取消。只有成功领取才移除标牌、增加背包内容。
- Hunter 装备条件为 AND，未鉴定装备不匹配；通货按选中种类显示；背包丢出的物品绕过 Hunter。
- 最多排布最近的 96 个标牌，按原方法尝试 100 个位置避免重叠。
- 原型初始使用“全部掉落”评审场景，显式关闭过滤以展示各类标牌。`emptyHunter()` 原默认开启值保持不变，并有专门验证。

JS 源快照只在 UICreator 作者工具中运行，没有加入 UE 游戏运行时。

## 主工程后续接线差异

这轮交付是原型，没有替换运行中的 WBP。主工程基础掉落/拾取接口已存在，以下差异需要在采用原型时按此契约处理：

| 项目 | RuleStudio / 本原型 | 当前 Opus 展示层 |
| --- | --- | --- |
| 通货与征兆 | 专用颜色、等级符号 | 地面标牌仍主要按品质 |
| 标牌出现 | 完成落地后 | 当前按地面记录立即创建 |
| 拾取目标 | picking 高亮 | 缺选中状态绑定 |
| 地面详情 | hover / Ctrl 固定 | 尚未接入地面标牌 |
| Hunter 默认值 | 原模型 enabled=true | 当前 HUD 默认 false |
| 背包丢出物品 | 绕过 Hunter | 原生 UI 数据尚未携带 origin |
| 排布优先级 | 所有数量都按距离排序 | 当前超过 96 件时才选近处 |
| 排布垂直锚点 | 以原地面投影为顶部 | 当前原生 PlaceLabels 会向上减一个标牌高度 |

本原型不重写 DWRules。UE 接线继续采用 Lua / AS，C++ 仅提供已有数据/控件桥接所需字段。

## 验证与组合边界

`node --test tests/loot-prototype.test.mjs` 验证源快照一致性、掉落序列、领取校验、Hunter、96 个预算、排布和 UICreator 结构。页面“对照检查”验证实际浏览器状态。

`composition.json` 与 Controls 用于资源结构检查。尚未启动 PNG Canvas 组合，也没有导出 UE 纹理或 WBP；不把浏览器截图当作可导入的整屏 UI 贴图。
