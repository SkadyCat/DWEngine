# 左右抽搐与动画反复重启

本次修复位于独立的 3C 工程。默认启动及编辑器 Play 均使用稳定控制；窗口左上角显示 `STABLE CONTROL`。按 C 可切回 `ORIGINAL REPRODUCTION`，专门用于对比原始问题。

## 实际原因与修改

1. 连续命中每次都调用 `PlayAnimation(hit)`，把受击片段重置到第一帧；攻击和受击也能互相打断。现在伤害始终照常结算，表现请求会合并，已开始的攻击或受击播放完整；死亡仍立即生效。
2. 原控制约每 0.4 秒重新选择最近敌人，攻击中也能换目标和瞬间转身。现在保持有效交战对象；新目标须明显更近且满足保持时间，才允许替换。攻击命中对象独立保存，动作期间锁定朝向，其他时间按每秒最多 300° 转向。关闭原生控制器对 Pawn 朝向的额外写入。
3. 单一距离阈值让接近和停止来回切换。现在追击开始、停止采用不同距离；待机与移动使用实际速度的不同阈值，并保持至少 0.25 秒，减少边界抖动。稳定模式去掉周期性的强制后退，避免用前进动作表现反向滑动。
4. 原控制把每帧逻辑时间截到 0.05 秒，而 UE 动画仍按真实帧时长播放，低于 20 FPS 后动作与计时逐渐脱节。稳定模式统一使用真实帧时长；停下时同时清空排队的移动输入，攻击、受击、死亡不会继续消耗旧移动请求。

模型、骨架及动画资源没有修改。正式 Opus 的规则引擎、伤害与存档没有修改；以下战斗事件均是实验场训练逻辑。

## 100 人实跑结果

每组 40 秒，100 个单位、34/33/33 三阵营、15 种模型，各 40,000 行运行采样。三组均覆盖待机、跑动、步行、攻击、受击、死亡。

| 指标 | 原始模式 60 FPS | 稳定控制 60 FPS | 稳定控制 15 FPS |
|---|---:|---:|---:|
| 受击片段尚未结束就从头重启 | 1,103 | 0 | 0 |
| 非死亡造成的动作提前切断 | 784 | 0 | 0 |
| 动作期间更换有效目标 | 355 | 0 | 0 |
| 动作期间朝向变化超过 3° 的帧 | 874 | 0 | 0 |
| 单帧朝向突变超过 35° | 478 | 0 | 0 |
| 大幅转向在 0.25 秒内反向 | 6 | 0 | 0 |
| 攻击中移动样本比例 | 31.89% | 0% | 0% |
| 攻击 / 受击 / 死亡事件 | 1730 / 1684 / 87 | 1230 / 1173 / 55 | 1276 / 1226 / 55 |

事件计数来自逐帧累积计数器，采样后对每个单位取最大值汇总。“动作期间”不含动作结束后的第一帧；死亡强制中断单独处理。“攻击中移动”是攻击已播放超过 0.15 秒且 Actor 速度大于 25 cm/s 的样本。它不等于鞋底接触误差。

这次同时修正了选敌、动作优先级、移动和计时，因此战斗事件总数会变化。两组稳定模式的计时与真实时间相等；其中低帧率组的帧时中位数为 66.67 ms。结果来自具体测试，不能保证所有场景、所有资源均不存在其他视觉问题。

带实际渲染的交互窗口另外连续采样 119.92 秒：4,321 次攻击、4,128 次受击、215 次死亡，上述重启、提前切断、动作中换目标、动作中转向与大幅反向计数仍均为 0，帧时中位数 54.23 ms。

复现命令：`Tools/Verify-Stability.ps1`。原始结果在 `stability-analysis.json`；旧版初次诊断备份在 `BeforeStability/`。
