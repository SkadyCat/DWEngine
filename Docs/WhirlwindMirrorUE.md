# 旋风复制体重叠修复

当前 `whirlwind_swarm` T1 配装的初始数量是基础 1 枚，加武器与手套各 1 枚，共 3 枚。更多旋风由真实命中生成镜像地面、投射物进入地面后复制产生，不是施法时固定发射几十枚。

问题位于原生 `DWRuleModernCombat.cpp`：镜像的 `ChildState=*St` 继承了父体的游走原点、随机种子、朝向和剩余转向时间。真实载体数量能增长，但后代沿着父体的同一路径重叠。修复前瞬态实测一次施法产生 96 次镜像、峰值 99 个载体，第 7～8 秒仍只有 3 个相隔至少 1 米的中心。

现在复制体在实际出生位置建立自己的游走原点、随机流及转向时钟，对应网页 clone/newState 的独立游走行为。实际投射物年龄、寿命、伤害、地面接触能力与进入判定继续继承；没有改动数量词条、镜像概率或规则数据。复制体仍须退出再进入镜像地面，且不刷新原始寿命。

## 验证

- `Tools/Verify-WhirlwindParity.ps1`：独立 NullRHI 瞬态游戏、当前 T1 配装、一次实际原生施法、20 个高血静靶；修复后峰值 18 个，最多 16 个分离中心、15 个方向，最终清零。
- `Tools/Verify-WhirlwindParity.ps1 -Visual`：D3D 实机验证峰值 27 个，最多 17 个分离中心、19 个方向，最终清零；`Saved/Verification/WhirlwindParity/native-after.png` 显示独立移动的旋风。
- `DungeonWorldOpus.Recent`：7 项原生机制检查全部通过。新增 `MirrorIndependentRoaming` 检查出生原点、独立随机流、转向时钟、实际分离、伤害/年龄继承及原寿命到期。
- 网页当前同 T1 配装，种子 18 的参考实验峰值 118、镜像 115；空场初始 3 枚。不同随机过程与命中时机不要求产生相同数量，复现重点是复制体能独立游走。原始结果、修复前后日志、自动化报告和源码/二进制指纹见 `Saved/Verification/WhirlwindParity/`。

测试使用 `DWOTransient`，不加载或写入用户角色存档。实际游戏预览由共享施法验收任务统一恢复，避免重复启动并争用 DLL。

## 2026-10-26：持续移动、地牢地面与身前发射

进一步定位到折返后的错误减速：原生游走用 `(Position-Start)/Dt` 作为扫掠位移载体，又把它当作下一步的真实速度。折返和转向缩短净位移，因而逐次损失速度。现在独立保存物理游走速度；真实的加速、减速词条继续参与计算。镜像复制体继承物理速度，不继承缩短的位移速度。

地面通过宿主 `ProjectGround` 回调读取真实静态碰撞的高度和法线；接触判定使用该平面，并阻断隔墙接触。没有实际地面不生成漂浮地面。旋风、现代地面及既有持续地面的显示改为沿真实地面摆放。当前地牢的 191 个可走点实测仍都是 Z=0；另以 Z=310cm 的抬高平台和空洞分别验证投影和拒绝生成。没有把当前平地上“看不到”全部归因于地面高度。

Niagara 原包保持不变，派生 `/Game/WebVFX/Systems/NS_OpusWhirlwind`。十二个旋风发射器的 `FloatFromCurve → VectorFromFloat001 → ScaleMeshSize.Scale Factor` 由 0.5→1 改为常量 1；编译后的对应曲线同步更新。七个物理/元素显示映射使用派生资产，无额外出生预热。出生 0.1/0.7/2 秒已分别截图检查。

最新“身前向外随机推出”在 AS 实际攻击 Release 处处理发射位置和初始随机朝向。两套旋风预设原本自带 `proj_layout_ring`，会正确产生向后弹体；已将这两个预设戒指改为 `proj_layout_fan`。现有用户存档仅迁移相同 UID 的这两个作者预设戒指，逐项确认其余档案字段相同并保留迁移前备份。没有加入规则 VM 技能特判，也没有扩展网页规则字段。
