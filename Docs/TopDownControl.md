# Zero 3C 与俯视镜头

主工程 `ADWOHero` 继承 Zero 的 `ACleanNetworkCharacter`，使用原生 `UCleanNetworkMovement` 和 `UCleanMotionAnimInstance`。退役原 APawn 的逐帧坐标位移和方向序列硬切。

来源：`G:/DungeonWorldZero/Plugins/MoonScholar3C` 原生移动、Motion Matching、动作蒙太奇及姿态连续节点；`Script/MoonScholar/Clean3C.as` 的相机、瞄准、移动意图、动作锁、移动打断和翻滚后朝向恢复；`clean3c/roll.lua` 的八方向选择迁为 AS。相机直接使用 Zero 的 `CleanCameraFollow.as`，只移除源文件的临时绿色调试轨迹。

| 项目 | 当前配置 |
| --- | --- |
| 固定镜头 | Pitch -60°，Yaw 0°，距离 2200，FOV 60°，目标上移 75 |
| WASD | 先归一化，再按镜头 Yaw 转换到世界方向，独立于角色朝向 |
| 鼠标 | 视口内坐标投射到角色脚底平面，20 cm 死区，失效时保持上次朝向 |
| 镜头跟随 | Zero 原组件，物理移动后更新，速度系数 10；传送重置，不随角色朝向旋转 |
| 移动手感 | 原生 CharacterMovement，1700 加速度、2000 制动，行走 300、跑步 500；叠加 DWRules.MoveScale |
| 胶囊与地面 | Zero 的半径 34、高度半长 98；真实地面与墙碰撞，替换手写坐标夹紧 |
| 动画 | 原 ChannelMobile 图、26 个 Motion Matching 数据库、原蒙太奇混合与 IK；Wizard 仍复用原指骨重定向图 |
| 翻滚 | 原 Mocap114 八方向 DA、播放倍率及根运动；保持朝向锁和有界恢复，替换瞬移 |
| 施法 | 输入先启动 Zero 原施法蒙太奇；源动画 Attack Release 标记才调用 DWRules、扣费和释放。Action End 结束动作与移动/转向锁，输入可立即开始下一次起手，不等整段动画或淡出结束。没有额外的固定输入频率；技能自身冷却仍由规则引擎检查。出手前移动、受击、死亡或替换动作会取消待释放的施法 |
| 目标 | 手动施法按鼠标地面位置和方向释放，可朝空地施法；瞄准的敌人死亡不会取消手动动作。自动索敌仍选择当前规则世界存活的敌人，自动攻击的目标失效时取消待释放动作 |
| UI 输入 | 弹窗、文本编辑及暂停停止移动和施法；关闭后等待已按下的战斗键松开 |

鼠标优先使用 Zero 的可见性射线，再使用脚底平面；规则出手坐标保持脚底以上 60 cm 的原战斗平面。Shift 闪避、Q/E/T/G 道具保持用户选择；CapsLock 切换行走。Ready 和 Cleared 阶段可移动并手动释放技能，技能、冷却、资源和投射物按原生规则继续运行，准备阶段不开始怪物波次和计时；开始战斗仍需手动确认。掉落自动走近通过同一 CMC，WASD 仍会取消走近。

施法请求记录当前技能、瞄准方向和目标，保留规则出手点相对角色战斗平面的偏移；实际释放时跟随根运动后的角色位置。松开施法键会完成已开始的动作；暂停会冻结动作并在继续后恢复。切换技能或打开输入弹窗会取消尚未释放的动作。没有额外的即时施法路径，也没有在 AS 中重新计算伤害或资源消耗。

本次动作衔接修复没有修改规则引擎。按用户要求，从网页 `Content/Rules` 与 UE `Content/RulesTower` 的 `WebTraits/create_whirlwind.json` 删除额外的 `cooldown: 2` 配置；其他技能的冷却配置和引擎冷却检查保留。原命中球通过随角色附着的规则目标保持脚底以上 60 cm、半径 45 cm，在创建玩家规则会话之前注册；速度使用真实 CMC 结果。几何查询只选 WorldStatic 对象，避免新物理胶囊误挡怪物视线或规则几何查询。

Zero 原生插件只将旧账号/UI 角色父类换为 ACharacter，并暴露引擎已有根运动缩放 setter；未带入 TopDownRuntime、旧 UI 资产、账号和旧伤害链。资产依赖清单见 `Zero3CAssets.json`，准备检查见 `Zero3CPrepared.json`，完整接入状态见 `Zero3CIntegration.json`。

## 验证

执行 `Tools/Verify-Hero.ps1 -Render` 或 `Tools/Verify-TopDown.ps1 -Render`。默认使用隔离物理平台，`-Dungeon` 使用当前正式地牢并等待导航就绪。只在显式瞬态测试模式运行，不读取或写入存档。测试关闭后台节流并提高准备期间的加载预算，正式运行保留原有 2ms 分帧预算；不能将后台测试耗时当作正式帧率。

- 使用实际摄像机投影，验证角色朝向 0°、90°、180°、270° 时 W 向屏幕上方、D 向右。
- 真实 CMC 加速/制动与 MM 轨迹、数据库选择；不是手动推进循环模拟。
- 验证 30 / 60 / 120 FPS 下镜头跟随结果一致。
- 真实八方向根运动行程、起手无瞬移、移动打断施法、暂停、原生施法/闪避和怪物伤害死亡。
- 战斗中验证起手和打断均不扣费、不释放；源动画真实 Notify 才提交原生施法并扣费；错误序列、重复或取消后的 Notify 无效；长按三次动作对应三次释放。
- `-DWOTransient -DWOHeroArena -DWOAttackEndTest` 验证源动画实际 End 通知：三轮 End 时动作状态为 0、转向/移动锁已解除，第一次后续输入立即开始新动作；旋风没有额外冷却，回响仍受原有 5 秒规则冷却限制。结果为 `Saved/Verification/AttackEnd/after.log`。
- `Tools/Verify-FreeCast.ps1` 验证零怪物场景中的手动空放和长按连放、实际源动画标记扣费、真实原生投射物、暂停禁止施法、自动索敌不能使用旧瞄准，以及准备/清层阶段不推进波次。
- 空放夹具等待新建的源动画图完成初始化与首次求值后才注入测试输入，避免将图创建帧当成已经可交互的稳定帧；没有在正式施法流程加入等待计时器。
- 起手后让鼠标瞄准的敌人死亡，手动动作仍在原出手标记释放一次；移动打断和重复 Notify 的保护保持生效。
- 重试重建主角并回到 Ready，保留原始存档不变量检查。

日志与画面：`Saved/Verification/Hero/visual-gameplay.log` 及同名图片目录。旧 Beta/APawn 的测试结果不代表本实现已通过；以这次实际执行结果为准。
