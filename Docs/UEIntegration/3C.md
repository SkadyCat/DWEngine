# CustomTools/3C 接入 Opus

来源是 `CustomTools/3C/ThreeCLab.uproject` 的稳定控制版本。正式怪物使用 `Script/Opus/Combat3C/Enemy.as`；玩家自动瞄准的目标保持位于 `TopDownControl.as`。

## 已接入的行为

- 怪物由原来的逐帧位置平移改为原生 CharacterMovement，保留地牢导航路径，使用胶囊碰撞和 RVO 避让。移动速度、停止距离仍读取原生怪物规则。
- 攻击和受击表现期间锁定移动及朝向；连续受击合并为表现请求，死亡立即打断。生命、护盾与伤害仍由 DWRules 结算。
- 移动时最多每秒转向 300 度；使用平滑的真实位移方向，低速碰撞噪声不接管朝向。追击距离与移动状态分别使用进入、退出阈值。
- 前进约 0.28 秒仍缺少净位移时进入受阻等待，保持待机与朝向。身体大小的胶囊扫掠持续畅通 0.18 秒、等待至少 0.3 秒后恢复，避免定时撞墙重试。
- 待机、移动、攻击、受击通过原生 Montage Slot 进行 0.22 秒 Cubic 混合，死亡为 0.12 秒；动作末帧保留至下一动作接管。36 种现有模型共 229 个动作均有过渡资源。
- 实验场标定的 15 种人形模型使用独立走路、跑步基准；播放倍率跟随实际位移，停止时可以为零。其他谱系保留原步速基准，法师无可用支撑步态的限制沿用实验场结论。
- 接入 12 种模型的 14 个外置装备部件，以及另外 3 种模型的自带装备；保留标定挂点、缩放和握持姿态。外观装备不加入属性或伤害计算。
- 玩家自动瞄准保持有效交战对象，新对象明显更近且保持时间达到 1.25 秒才替换；目标死亡立即重选。手动鼠标瞄准、原有施法释放通知、翻滚和眩晕机制继续使用 Opus 现有实现。
- 怪物动作计时与 UE 动画使用同一实际帧时长，暂停冻结完整动画通道，包含正在混合淡出的姿态。

## 规则边界与资源

`TickMonsterSkill` 仍在每个战斗帧调用一次，原生规则决定技能选择、释放、冷却、控制与伤害。表现恢复不会增加技能冷却，也不会阻断规则已经允许的后续释放；同一已提交动作期间的重复表现请求合并。实验场的训练伤害、复活、三阵营选敌、周期步行练习、相机和 HUD 没有迁入。

导入的 91 个实验场 Montage 和 43 个装备依赖逐文件校验；其中 27 个装备依赖原先缺失。另外为 Opus 的其他模型生成 138 个只引用原动画的 Montage。原模型、骨架、动画与规则目录未重写。

资产准备命令：

```powershell
python Tools/Migration/Import-3C.py
# 冷启动 UE Python commandlet 执行 Tools/Migration/Complete-3CAssets.py
```

运行时资产先进入原有异步准备队列，再逐帧创建怪物。AS 负责行为和绑定，没有新增 C++ 模块、JS 游戏逻辑或实验场 UI。

## 验证

```powershell
Tools/Verify-3C.ps1 -FPS 60
Tools/Verify-3C.ps1 -FPS 15
Tools/Verify-3C.ps1 -Render
Tools/Verify-3C.ps1 -Crowd
Tools/Verify-Dungeon.ps1
Tools/Verify-Hero.ps1
```

证据保存在 `Saved/Verification/ThreeC`。3C 验证覆盖模型与装备、实际骨骼过渡、连续受击、步态倍率、原生墙体/怪物堵路及放行、真实怪物施法、动作锁定、暂停、自动瞄准和死亡。每次 3C 验证使用 `-DWOTransient`，核对正式存档 SHA256，禁止用恢复旧存档代替未改动检查。

地牢回归已通过导航追击、原生伤害和掉落及楼层切换；玩家回归已通过移动、八方向根运动翻滚、施法通知、连续施法、受击死亡和重试。

60 FPS 专项、15 FPS 专项与 D3D 渲染专项均已通过。装备在原生求值后的握持误差最大约 0.000025 cm。两种阻挡用例均保持待机、位置和朝向稳定，移开障碍后恢复；本次前进 25 cm 的恢复时间约为 0.60–0.80 秒。15 FPS 专项共记录 229 个行为帧，平均帧时约 71.64 ms，包含一次 400 ms 的长帧。这是指定用例的结果，不能代表 300 单位的渲染帧率。

低帧率比较在资产和普通遭遇准备完成后限速。初次将整段异步资产入队也限为 15 FPS，并同时预载全部 36 种模型，触发了准备超时；保留 `initial-low-fps-loading.log`。最终比较将资产加载与战斗分开，没有延长正式遭遇的超时或修改游戏准备逻辑。

已补充新表现资源的 Cook 目录；未执行完整发行包打包。渲染截图来自真实 UE 测试场，墙体/怪物阻挡断言使用实际原生碰撞和逐帧位置，截图不代替这些断言。

300 怪物的正式地牢分帧准备与重开回归通过：两次均生成 299 个普通怪物和 1 个首领，每帧最多创建 1 个，准备期间挑战计时为零、玩家和战斗保持冻结，完整发布后才恢复。首次准备约 9.45 秒，复用缓存后的重开约 5.50 秒。该项验证生成、发布和缓存，不是 300 怪物的渲染帧率基准。记录见 `crowd-300.log` 和 `crowd-300-receipt.json`；仍使用瞬态存档，正式 Profile SHA256 未变化。
